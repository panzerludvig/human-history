# Incremental Design

The governing rule for how Iron and Blood is designed: start with the smallest set of core concepts that produces a playable loop, and expand only from what is already working.

---

## The Rule

1. A concept enters [[Design/Core Concepts]] only if the current core is incomplete without it.
2. A concept is not elaborated beyond what the next playable increment needs.
3. Ideas that aren't needed yet go to [[Meta/Open Threads]] or [[Meta/Quick Notes]] — they are not written up as design notes.
4. Each design note carries a status from [[Meta/Status Vocabulary]], so it is always clear what is decided versus speculative.

---

## Why

Delegate tried to settle everything up front — agents, objects, tech, diplomacy, weather, terrain — before any of it was tested. The result was a wide set of interlocking open questions with no way to resolve any of them, because each depended on the others. Starting narrow means each decision can be checked against something concrete before the next one is built on it.

---

## How to Apply

When a new idea comes up, ask: *does the current core break without this?* If not, park it. When a design note is being expanded, ask: *does the next increment need this detail?* If not, stop.
